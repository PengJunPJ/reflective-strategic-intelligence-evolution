# 领域文档

本文件说明工程技能在探索代码库时应如何读取和使用本仓库的领域文档。

## 开始探索前需要读取

- 仓库根目录中的 `GLOSSARY.md`；或者
- 如果根目录存在 `GLOSSARY-MAP.md`，则按照其中的映射读取与当前主题相关的各上下文 `GLOSSARY.md`；
- `docs/adr/` 中与即将处理的区域相关的架构决策记录。

如果这些文件尚不存在，直接继续，不要提示缺失，也不要预先建议创建。`/domain-modeling` 技能会在领域术语或架构决策真正明确后按需创建这些文件。

## 文件结构

本仓库采用单上下文布局：

```text
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-示例决策.md
│   └── 0002-另一项决策.md
└── src/
```

## 使用术语表中的词汇

当输出内容需要命名领域概念时，包括议题标题、重构建议、假设或测试名称，应使用 `GLOSSARY.md` 中定义的术语，不要改用术语表明确避免的同义词。

如果所需概念尚未出现在术语表中，首先重新判断该说法是否属于本项目；如果确实存在术语缺口，则记录下来，供 `/domain-modeling` 处理。

## 标明与架构决策的冲突

如果输出内容与现有 ADR 冲突，必须明确指出，不得静默覆盖。例如：

> 与 ADR-0007（订单采用事件溯源）冲突，但值得重新讨论，因为……
