### 2. 三项任务和合规红线

1. **红蓝高对抗指挥决策场景设计**
   - 交付 1 套自设红蓝对抗场景：场景描述报告 1 篇和配套数据 1 份。

2. **指挥决策智能体反思演进**
   - 必须提供基线智能体代码框架，并实现快速、稳定、有限交互轮次的反思演进。

### 3. 官方数据模型与测试集

基线场景是反无人机集群场景，用四元组 `{T, W, P, V}` 描述：

- `T={T1,...,Tm}`：蓝方目标无人机集合，目标数为 `m`；
- `W={W1,...,Wn}`：红方反无武器集合，武器数为 `n`；
- `P=[p_ij]`：`n×m` 毁伤概率矩阵，`p_ij` 表示武器 `Wi` 对目标 `Tj` 的毁伤概率；
- `V=[v_j]`：`1×m` 目标价值向量，威胁越高的目标价值越高。

初赛设置 `20×50` 和 `200×500` 两种规模，每种规模 5 个独立用例，共 10 个标准测试用例。变化包括：

- 无人机突然增多；
- 反无设备被毁；
- 对我实施干扰；
- 有无人混合突防新战法；
- 无人机性能突变。

审核通过的队伍会定向收到两个规模的“无对抗变化”基线用例；其余测试用例不对外发布。复赛使用官方 1 套基线场景加优选的 4 套参赛者自设场景，每套场景 10 个标准用例。

数据版权规则：主办方基线数据版权归主办方，仅用于本赛事；参赛者自设数据遵循“谁创造、谁拥有”，主办方保留宣传、展示和非商业性使用权。

### 4. 运行环境、I/O 和提交形态

- 语言：Python（推荐）、C++、Java 等主流语言。
- 框架：PyTorch、TensorFlow、Keras、Scikit-learn、ONNX 等，版本不限，但必须在 `dockerfile` 中明确标注。
- 环境：Linux（推荐 Ubuntu 20.04+），Docker 容器化部署。
- 模型：文字原文为“大赛指定的开源预训练模型（Qwen3.8-27B 等）”；该型号需官方澄清。
- 输入：容器 `/input` 目录中的 JSON 文件，命名 `scene<S>_<I>.json`，`S=1` 对应 `20×50`，`S=2` 对应 `200×500`，`I=1..5`。
- 输出：必须同时支持关闭和开启反思，在 `/output/norethink` 与 `/output/rethink` 下产生与输入同名的 JSON 文件。输出格式错误得分为 0。
- 大模型 API 配置：必须配置 `api_key`、`base_url`、`model` 三项；`temperature`、`max_tokens` 等请求体参数可选。
- 算法交付：初赛线上提交代码与镜像 `dockerfile`，由主办方在统一算力服务器部署、执行并多轮评价；算法程序命名为 `team_number_image_版本号.tar`。

上述只是目录、命名和运行契约，**不是完整的 JSON 字段级 Schema**。官网明确说“具体要求参考后续发布的代码提交模板”。

### 5. 评分规则

#### 初赛（100 分）

| 评分项 | 分值 | 官方说明 |
| --- | ---: | --- |
| 红蓝对抗场景设计 | 10 | 线上专家评分；新颖性、复杂性、合理性、作战需求贴合度 |
| 反思式决策解决方案 | 40 | 线上专家评分；反思的创新/多样/收敛/合理/可解释，知识抽取建模与知识驱动决策 |
| 智能体反思速度 | 25 | 对每个用例按求解时间正序排名；第一名 2.5 分，最后一名或超过 10 分钟为 0 分；10 个用例求和 |
| 智能体反思效果 | 25 | 每用例 `2.5 × λ × P2/Ptotal`，10 个用例求和 |

官方对公式量的定义：

- `P1`：反思演进前的期望毁伤价值；
- `P2`：反思演进后的期望毁伤价值；
- `Pset`：有限时间内最优解值的 90%；
- `Ptotal = Σ_j v_j`：目标总价值；
- `λ=1`，当 `P1 ≥ Pset`；否则 `λ = 1 - α·(Pset-P1)/Pset`。

这意味着不能通过故意弱化基线来夸大反思增益；基线必须尽量达到 `Pset`。但 `α` 的数值尚未发布。

## 官方材料中需注意的内部不一致

1. B05 赛题 API 的 `description`、`dataset`和 `criteria` 顶层元数据写的是泛化“垂直行业智能体应用”，与同一对象中 `lede` 和 `detailContent` 的“反思式指挥决策”完全不同。本研究依据 B05 详情正文和评分表，不使用错置的顶层元数据。
2. 章程称“挑战赛 5 条赛道、9 道赛题”；北京理工大学 2026-10-22 通知称“六大赛道、十项赛题”，是把数智创意赛道也计入总数。两者对 B05 无实质冲突。
3. B05 文字中的“Qwen3.8-27B”命名异常，必须以主办方澄清或实际 API `model` 值为准。
4. 复赛交付物正文从“成果一”跳到“成果三”，属编号或内容缺失，不应据此推定不存在第二项交付。

## 对当前技术路线的直接影响

- **基线不能弱**：初赛效果分存在 `λ` 惩罚；应以任意时可行的强基线优先逼近 `Pset`，反思只在此上增益。
- **严格时限**：官方 10 分钟是单用例得速度分的硬上限，不是建议时间；内部截止时间应更保守，并输出 best-so-far。
- **公平对照是接口约束**：程序必须产生同名的 `norethink`/​`rethink` 结果，因此两模式应共用输入解析、硬约束检查、种子和基线求解核心，只差反思外环。
- **接口适配必须独立**：JSON Schema 仍待发布，不应让当前假设渗透求解器。
- **大模型不能在核心内循环**：官方未公布 API 额度与延迟，而又按时间排名；应让组合优化求解器负责每次分配，大模型只做低频、有界、可降级的反思候选生成。
- **容器与离线是主路径**：从第一个可运行版本开始就应用 Linux/Docker 和 `/input` → `/output/{norethink,rethink}` 做端到端回归。
